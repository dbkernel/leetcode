# 题解文件模板

本文件是 `Problems/` 下题解的统一骨架。新增题目时复制 [文件骨架](#文件骨架) 一节，
按注释里的占位符逐项填写；写完后过一遍 [自检清单](#自检清单)。

参考实现：[0001-two-sum.cpp](0001-0100/0001-two-sum/0001-two-sum.cpp)

## 目录与命名约定

```
Problems/
└── 0001-0100/                          # 按题号百位分桶，左补零到 4 位
    └── 0001-two-sum/                   # 4 位题号 + 短横线 + 官方 slug
        ├── 0001-two-sum.cpp            # 文件名与目录名保持一致
        ├── 0001-two-sum.go
        └── 0001-two-sum.py
```

- 分桶目录：`0001-0100`、`0101-0200` …… `1901-2000`
- 题号：LeetCode 中文站题号，左补零到 4 位
- slug：取官方链接末段，全小写、连字符分隔
- 非 LeetCode 题目（剑指 Offer、面试题、华为机考）沿用现有 `JianZhiOffer/`、
  `InterviewQuestions/`、`HuaweiJikao/` 的目录，不套用本约定

## 五段的写法要求

### 第 1 段 · 文件头

字段固定六项，顺序不变：题号题名难度、来源、链接、分类、题面、提示。
`分类` 决定这道题在 README 的哪个阶段被检索到，要写读者会用来搜的词，
不要写「简单」「数组」这类几乎每题都成立的标签。

### 第 2 段 · 题面

逐字复制官方题面。个人的理解、类比、吐槽一律放到第 3 段，
不要把观点混进题面，否则半年后无法分辨哪句是题目要求、哪句是自己的解读。

### 第 3 段 · 解法

四小节，缺一不可：

| 小节 | 回答的问题 | 反面例子 |
| --- | --- | --- |
| 为什么慢 | 瓶颈在哪一步 | 「暴力法很慢」——没说慢在哪 |
| 换个角度 | 用什么视角消除瓶颈 | 直接贴代码 |
| 关键点 | 哪个动作的顺序 / 边界不能错 | 「注意细节」——等于没说 |
| 手推一遍 | 读者能否跟上两步 | 只写「如上例所示」 |

**关键点是整段的重心。** 它必须是一个可执行的动作约束，读者看完能自己检查代码
有没有写反。本题的「先查后插」是范例：顺序一颠倒，`[3,3]` 就会返回 `[0,0]`。

复杂度写**为什么**，不写套话。`空间 O(n)：最坏情况下前 n-1 个数都留在表里`
比 `空间 O(n)：使用哈希表存储` 有信息量。

### 第 4 段 · 代码

行内注释只写「为什么这样是对的」，不写「这一行在做什么」。

```cpp
// 差：把代码翻译一遍
// 在哈希表中查找 complement
auto it = seen.find(complement);

// 好：解释为什么安全
// 只在前缀里找：命中时 seen 中存的下标必然 < i，不会是自己
auto it = seen.find(complement);
```

单条注释超过 2 行时，先想清楚它该不该出现在这里；如果是在讲算法思路，
它属于第 3 段。变量名能表达的信息不要用注释重复，注释用来补充
变量名表达不了的**范围**和**约束**。

### 第 5 段 · 自测

- `main` 里至少覆盖：全部示例 + 一个边界或反直觉用例
- 用 `assert`，不要只 `printf` 看输出
- 结果比较要按题意放宽：题面说「顺序任意」，就不许断言固定顺序（见 `samePair`）
- 末尾打印一行可见的输出，否则全部通过时无法区分「跑通了」和「没执行」
- 提交平台的入口签名不能改：`main` 和辅助函数放在 `Solution` 之外

**其他语言的等价写法**（同一道题的多语言文件保持同一套五段结构，只替换工具）：

| 语言 | 断言 | 结果比较 | 可见输出 | 入口签名 |
| --- | --- | --- | --- | --- |
| C++ | `assert` | 排序后比较数组 | `cout` | `class Solution` + `int main()` |
| Go | 无 assert，用 `panic` 或 `if !ok` 显式报错 | `slices.Sort` + `slices.Equal` | `fmt.Println` | 顶层 `func twoSum` + `func main()` |
| Python | `assert` | `sorted(a) == sorted(b)` | `print` | `class Solution` + `if __name__ == "__main__"` |
| Rust | `assert!` | `sort_unstable` 后比较 Vec | `println!` | `struct Solution` + `impl Solution` + `fn main()` |

Rust 用 `rustc` 单文件编译时平台预置的 `Solution` 类型不存在，需要显式写
`struct Solution;`，并在注释里说明这是本地编译所需。

## 自检清单

复制到新文件后逐条核对，全部通过再提交。

**正确性**

- [ ] `g++ -std=c++17 -Wall -Wextra` 编译零警告
- [ ] `./可执行文件` 输出 `all tests passed`
- [ ] 断言不依赖题面未承诺的顺序或具体取值
- [ ] 有专门针对「关键点」的用例（写错顺序或边界时这条会挂）

**注释**

- [ ] 题面部分逐字复制，未混入个人解读
- [ ] 关键点写成动作约束，不是「注意细节」式的空话
- [ ] 每条行内注释都在解释「为什么」，不是复述代码
- [ ] 注释提到的 API 行为与实际一致（如 `insert` 不覆盖、`operator[]` 覆盖）
- [ ] 语气中性，比喻不影响跨题复用

**格式**

- [ ] 无 U+00A0 等不可见字符（`python3 -c "print('\u00a0' in open('f.cpp').read())"`）
- [ ] 行宽 ≤ 80 列
- [ ] 链接域名为 `leetcode.cn`，无旧域名残留
- [ ] 占位符 `{{ }}` 已全部替换

**仓库**

- [ ] README 对应阶段的表格已更新（状态、多语言链接、备注）
- [ ] 同一道题若在多处出现，各处的备注说法一致

## 何时不套用本模板

本骨架适用于**单解法、可独立运行**的题目。遇到下列情况按需裁剪，
但第 1、2、5 段保留：

- **多解法对比**（如「递归 / 迭代 / Morris」）：第 3 段可重复多次，
  每个解法一套「为什么慢 → 换个角度 → 关键点」
- **设计类题目**（如 LRU Cache）：没有「为什么慢」可写，
  改为「接口契约 → 数据结构选型 → 各操作的不变式」
- **纯构造 / 找规律题**：第 3 段可能只有一句观察，不必凑满四小节
- **需要平台特殊接口的题目**（如 `guess`、`Node` 定义）：照录平台给定的签名，
  注释说明为什么不能改成自己的写法
